# SKATE SHOP — storefront template

A storefront template for a skateboarding brand, built with Next.js (App Router),
React and TypeScript. The layout follows the reference shop the brief named:
full-bleed background video, a slim announcement bar, a logo-left header with
inline navigation, borderless product cut-outs on a four-column grid, a
slide-over cart and a minimal footer.

Everything in the repository is original placeholder material generated by the
scripts in `scripts/`. No imagery, copy, fonts or brand assets were taken from
the reference site — only the layout structure was used as a starting point.

The store is called **SKATE SHOP** only because a template needs a name. Put
your own brand in `src/config/site.ts`; the header wordmark, page titles, footer
and announcement copy all read from that file.

## What works

- **Navigation**: exactly four tabs — SHOP, VIDEO, SALE, PREVIEW. SHOP opens a
  small collection menu (the four tabs stay the only top-level items).
- **Catalogue**: 17 products across decks, tees, tops, headwear and accessories,
  with collection filtering, sale pricing, sold-out states and a lookbook page.
- **Product pages**: image gallery with alternate photo, size picker, quantity
  stepper, add to bag, and related products.
- **Cart**: add from a product page or quick-add from a card, slide-over drawer,
  quantity changes, remove, subtotal and free-shipping threshold, dedicated cart
  page, and persistence in `localStorage` across reloads.
- **Accounts**: log in with the demo account, guarded account page, sign out.
- **Video**: a deferred-player reel page that only loads a clip after the
  visitor presses play.
- **Responsive**: two-column grid on phones, four-column from 990px; mobile
  drawer navigation; no horizontal overflow at 390px.

## Project structure

```
src/
  app/                     routes (App Router)
    layout.tsx             shell: providers, background, header, footer, cart drawer
    page.tsx               home: latest drop, decks, video band, sale
    shop/page.tsx          catalogue + collection filter (?collection=decks)
    sale/page.tsx          discounted products
    preview/page.tsx       lookbook grid
    video/page.tsx         reel of deferred players
    products/[slug]/       product detail (statically generated per product)
    cart/page.tsx          bag + order summary
    login/page.tsx         sign-in form
    account/page.tsx       guarded account page
    info/[slug]/           contact, shipping, terms, privacy
  components/
    layout/                announcement bar, header, mobile menu, footer, backdrop
    product/               card, grid, gallery, purchase panel, section heading
    ui/                    logo, icons, price, quantity stepper, button classes
    video/                 deferred video tile
  config/
    navigation.ts          the four tabs + collection definitions
    site.ts                brand copy, announcement, footer links
  features/
    cart/                  cart store, provider, drawer, cart page view, line row
    auth/                  auth store, useAuth hook, login form, account view
  lib/
    catalog.ts             the product data (single source of truth)
    format.ts              money helpers
    types.ts               domain types
```

The rule of thumb: **routes in `app/`, reusable pieces in `components/`,
stateful domains in `features/`, data and helpers in `lib/`, strings and
navigation in `config/`.**

## Replacing the placeholders

### Product images

Every product photo is a transparent PNG cut-out in
`public/media/products/`, so it can float over the background video the way the
reference does. Replace a file and keep the filename:

```
public/media/products/deck-01.png     → your deck photo (transparent PNG)
public/media/products/tee-01.png      → your tee photo
```

To add a product, add an entry to `PRODUCTS` in `src/lib/catalog.ts`. Image
paths are plain strings, so you can point at any file under `public/`.

### Video

```
public/media/video/bg-loop.mp4    fixed background loop (plus bg-loop.jpg poster)
public/media/video/clip-01.mp4    reel clips (plus .jpg posters)
public/media/video/clip-02.mp4
public/media/video/clip-03.mp4
```

Regenerate the placeholder clips with
`./scripts/generate_video_placeholders.sh` (requires `ffmpeg`), or drop in your
own edits using the same filenames. Keep the background loop short and muted —
it autoplays behind every page.

### Logo and brand

- Mark and wordmark: `src/components/ui/Logo.tsx` (inline SVG).
- Favicon: `src/app/icon.svg`.
- Name, tagline, announcement, contact and footer links: `src/config/site.ts`.
- Colours, type scale, spacing and radii: the `:root` block in
  `src/app/globals.css` (`--color-acid`, `--color-periwinkle`, `--color-ink`...).

Changing those tokens rebrands every surface; no component hard-codes a brand
colour.

### Catalogue and copy

Products, prices, colourways, sizes and descriptions live in
`src/lib/catalog.ts`. Prices are integer cents (`7500` = $75.00), which keeps
money arithmetic exact.

## Cart

The cart is a small external store (`src/features/cart/cart-store.ts`) read
through `useSyncExternalStore`. The state machine is a pure reducer that you can
test without React, and the store handles the two awkward parts for you:

- the server snapshot is always empty, so server and client markup agree;
- the persisted cart is read once, on the first subscriber, and written back on
  every change.

`CartProvider` only adds drawer visibility and derived values (line totals,
count, subtotal). Storage is versioned (`skate-shop.cart.v1`) and validated on read,
so a corrupt or outdated payload cannot break the page.

## Auth

Auth is a **front-end only demo**. `src/features/auth/auth-store.ts` validates
the hard-coded demo account and stores the session in `localStorage`; there is no
server session, so this is not real security and must not be used as-is for
anything private.

The account page is guarded on the client (it redirects to
`/login?next=/account`), and the `next` parameter is restricted to same-site
paths to avoid an open redirect. To go live, replace `signIn`/`signOut` in the
store with calls to a real provider and protect the route on the server too.

## What is intentionally not included

- Payments and checkout — the checkout button explains that the template stops
  at the cart.
- A database, inventory, tax and shipping calculations.
- Search, wishlists, discount codes, newsletters, analytics.
- Real policy text — `src/app/info/[slug]` ships with clearly marked
  placeholders.

## Accessibility and behaviour notes

- A skip link, visible focus rings, labelled icon buttons, and `aria-current` on
  the active tab.
- The cart drawer and mobile menu trap Escape, lock background scroll, and the
  drawer keeps Tab focus inside itself.
- Motion is reduced when the visitor prefers reduced motion (the background
  video is replaced by its poster).
- Empty, sold-out and error states are explicit rather than silent.

## Verification

Checked on a production build at 1440×950 and 390×844:

- `npm run lint`, `npm run typecheck` and `npm run build` pass.
- Add to bag → drawer → reload (cart persists) → quantity change → empty bag.
- Quick add on a one-size item.
- Wrong password shows an error; the demo login reaches `/account`; sign out
  returns home; a signed-out `/account` redirects to `/login?next=/account`.
- Unknown product slugs return a 404; collection filtering returns the right
  products.
- No console errors, and no horizontal overflow on any page at 390px.
